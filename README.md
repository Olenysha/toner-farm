# 🖨 Тонер-фарм

Система учёта расходных материалов (тонеров/картриджей) для IT-отдела.
Работает локально в корпоративной сети, управление — с телефона
через сканирование штрихкодов EAN-13 на коробках.

## Возможности

- **Сканирование EAN-13** камерой телефона в непрерывном режиме (html5-qrcode), со звуком и вибрацией
- **Установка тонера в 3 касания**: скан → тап по принтеру на карте → «Да»
- **Несколько предприятий**: у каждого свои этажи, планы и принтеры; переключение на карте, склад и справочники общие
- **Интерактивная карта этажа** с pinch-to-zoom: статусы принтеров цветными индикаторами (🟢🟡🔴⚫), размер иконок и подписей настраивается (запоминается на устройстве)
- **Автосписание** старого тонера при замене (пишется в историю как `auto_depleted`)
- **Склад по количеству**: приход/списание N штук по EAN, остатки по моделям и по принтерам (страница «Наличие»)
- **Обучение новых штрихкодов**: неизвестный EAN → форма с названием, цветом, совместимыми принтерами
- **История операций** с фильтрами и экспортом в Excel
- **Статистика**: замены по месяцам, средний срок службы, топ принтеров, остатки (Chart.js)
- **SNMP-мониторинг**: фоновый опрос принтеров по IP каждые 10 минут — реальный уровень тонера (прогресс-бары в попапе), счётчик страниц, алерты с расшифровкой, метка давности опроса на карте; статус на карте по уровню (≤5% красный, ≤20% жёлтый)
- **Админка**: предприятия и этажи, принтеры (в т.ч. drag-and-drop по карте), barcode_map, смена плана этажа, резервные QR-стикеры (печать на A4)
- **Автобэкап** базы раз в день в `backups/` (хранятся последние 14)

## Стек

Python 3.13, Flask 3.1, SQLite, pysnmp 7 (asyncio), vanilla JS + CSS (адаптив, тач-френдли).
Все JS-библиотеки локальные (`static/js/`), без CDN. openpyxl для Excel, qrcode+Pillow для QR.

## Быстрый старт (Windows)

Просто запустить **`start.bat`** — он сам создаст виртуальное окружение,
поставит зависимости и поднимет сервер. Если папку проекта перенесли на
другую машину (или обновили Python), `start.bat` заметит сломанный venv
и пересоздаст его под текущую версию Python.

Ручной вариант:

```bat
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python.exe app.py
```

> ⚠️ Папку `.venv` нельзя переносить между машинами — она жёстко привязана
> к пути установки Python. После переноса проекта удалите `.venv`
> или просто запустите `start.bat` — он сделает это сам.

Открыть `http://localhost:5000`. База `database.db` создаётся автоматически
с демо-данными.

## Запуск в Docker (Linux/Windows)

```bash
docker compose up -d --build
```

Сервер поднимется на `http://<host>:5000`. При первом запуске создаются
пустые БД; чтобы переехать с существующими данными, скопируйте
`database.db` (и `alerts.db`, если есть) в папку `data/` рядом с
проектом **до** запуска.

Что монтируется наружу (см. `docker-compose.yml`):

- `./data` → `/app/data` — `database.db`, `alerts.db`, `backups/`
- `./static` → `/app/static` — загруженные планы этажей и QR-стикеры

В контейнере сервер работает по HTTP — для доступа с телефона (камера
требует HTTPS) поставьте перед ним любой reverse proxy с TLS
(nginx, Caddy, Traefik) или используйте схему с mkcert на хосте.

## Запуск в сети с телефона (HTTPS, Windows)

Камера в мобильном браузере работает только по HTTPS, поэтому:

1. **`open-port-5000.bat`** — один раз, откроет порт 5000 в брандмауэре
   (сам запросит права администратора)
2. **`setup-https.bat`** — один раз в каждой новой сети: определит текущий IP,
   выпустит сертификат mkcert и пропатчит `app.py`
3. Установить корневой сертификат mkcert на телефон (один раз):
   файл `static/rootCA.pem` отправить на телефон → установить как сертификат ЦС
   (подробная инструкция выводится в конце `setup-https.bat`)
4. `python app.py` → с телефона открыть `https://<IP-ноутбука>:5000`

При смене сети/IP достаточно повторить шаг 2 — `app.py` читает IP из
`last_ip.txt` и подхватывает нужный сертификат.

> ⚠️ Сертификаты, ключи (`*.pem`) и `mkcert.exe` в репозиторий не входят
> (см. `.gitignore`) — не коммитьте их.

## Структура

```
toner_farm/
├── app.py               # Flask: страницы и JSON API, точка входа
├── db.py                # пути, схема SQLite, миграции, сид, бэкапы, хелперы
├── snmp_monitor.py      # фоновый SNMP-опрос принтеров (pysnmp 7, asyncio)
├── alerts_data.py       # справочник кодов SNMP-алертов (RFC 3805)
├── printer_ips.json     # карта «имя принтера → IP» для миграции
├── check_printers.py    # диагностика принтеров (SNMP + Web) из консоли
├── requirements.txt     # зависимости, зафиксированные версии
├── Dockerfile           # all-in-one образ (python:3.13-slim)
├── docker-compose.yml   # запуск + volume для данных
├── start.bat            # запуск на Windows: сам создаёт/чинит venv
├── setup-https.bat/ps1  # настройка HTTPS через mkcert
├── open-port-5000.bat   # правило брандмауэра для порта 5000
├── database.db          # SQLite (создаётся при первом запуске)
├── backups/             # ежедневные бэкапы БД
├── static/
│   ├── style.css
│   ├── floor_plan.png   # план-заглушка (планы этажей меняются из админки)
│   ├── js/              # html5-qrcode, Chart.js (локально, без CDN)
│   └── qr_codes/        # сгенерированные резервные QR
└── templates/           # base + index/scan/item/admin/history/stats/availability/qr_print
```

## Схема БД

- `enterprises` — предприятия
- `floor_plans` — этажи с привязкой к предприятию; у каждого этажа одна активная картинка
- `barcode_map` — EAN-13 → модель, цвет, совместимые принтеры, ресурс (page_yield)
- `toners` — учёт тонеров: `stock` / `installed` / `depleted`
- `printers` — справочник принтеров, координаты на карте, этаж (`floor_id`), 4 тонер-слота
- `operations` — журнал: `install` / `return` / `auto_depleted` / `stock_add` / `depleted`
- `snmp_readings` — история SNMP-опросов: уровни тонера (%), счётчик страниц, статус, алерты (JSON)
- `alerts.db` (отдельный файл) — справочник расшифровок кодов алертов
